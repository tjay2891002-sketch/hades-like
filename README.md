# Hades-like

用 **Godot 4.7 + GDScript** 从零手写的 2D 俯视角 Roguelite 动作游戏（个人独立项目）。

目标不是做一个能跑的 demo，而是把 Roguelite 的四条主线——**随机关卡路线 / 局内 Build 构筑 / 局外永久成长 / 打击手感 Juice**——完整串成一个闭环，并且把「单局状态」和「局外状态」的边界划清楚。

- 33 个 GDScript 文件 / 约 5600 行
- 3 个主场景（存档房 Hub / 战斗房 / Boss 房）
- 5 把武器、4 种敌型 + 精英变体、1 个三阶段 Boss
- 5 位神明 / 16 张祝福卡（重复获得升级，最高 4 级）
- 10 个 Autoload 单例

---

## 玩法循环

1. **存档房（Hub）**：用「英灵碎片」解锁武器与永久属性加成；在神像前供奉获得祝福。
2. **进战斗**：清空房间 → 从 3 扇出口门里选一扇，门上徽章标着「类型 + 敌人数 + 奖励倾向」。
3. **局内成长**：升级加血上限、捡金币、三选一祝福、背包满 10 张后进入替换模式。
4. **Boss 房**：打过三阶段 Boss，或阵亡。
5. **死亡结算**：本局获得的碎片写入 `user://meta.save`，永久解锁新神 / 新武器 / 新属性 —— 形成「越死越强」的正反馈。

> 关键约束：**武器只能在存档房选定，进入战斗后不可切换**。这是刻意的设计，让开局构筑决策有分量，而不是一局里骑驴找马。

## 核心系统

### 1. 战斗（`player.gd` / `enemy.gd` / `boss.gd`）

5 把武器由一张数据表 `WEAPONS` 驱动，靠字段组合区分机制，而不是复制五份逻辑：

| 武器 | 机制要点 |
| --- | --- |
| 短剑 | 高频近战，快但零击退 |
| 大剑 | 慢重击，范围大、击退强 |
| 法杖 | 远程自追踪弹，带冷却 |
| 长弓 | 按住蓄力（0.7s 满蓄），满蓄伤害 10 → 32 并附带 AOE |
| 坚盾 | 蓄力后持盾冲撞（全程格挡）；冲刺攻击可掷出回旋盾 |

- **翻滚**带短无敌帧 + 冷却；翻滚期间碰撞掩码降级，可穿出怪堆（见下方「工程难点 3」）。
- **冲刺攻击**：翻滚瞬间接攻击触发，伤害 ×1.5 并带前冲位移。
- **攻击快照**：出手瞬间定案伤害 / 击退 / 加成，本次攻击不受期间状态变化影响；命中列表在单次攻击内去重。
- **敌人状态机**：`CHASE → TELEGRAPH → (DASH) → RECOVER`。攻击前必有一段**可视化前摇**，玩家能靠走位或翻滚躲开——这是动作游戏「公平感」的地基，而不是难度旋钮。
- **四种敌型**：`CHASER` 追击哥布林 / `CHARGER` 蓄力冲锋史莱姆 / `SHOOTER` 保持距离放冷箭法师 / `TANK` 慢速高血高伤重装。房号越大混合越杂：前两房纯追击者当教学，之后逐步注入新怪。
- **Boss 三阶段**：按血量 66% / 33% 切阶段，切换瞬间放一轮环形弹幕作为「换阶段」信号；二阶段起叠加螺旋弹，弹幕密度对齐玩家 0.8s 翻滚冷却——**走位可解，不靠运气**。

### 2. 祝福构筑（`boon.gd` / `boon_manager.gd`）

- **机制型卡牌，不是数值克隆**。每张卡有唯一 `card_id`，重复获得 = 等级 +1（1→4）而非「同名换皮卡」。
- 5 位神明 / 16 张卡：宙斯（连锁闪电 / 风暴 / 闪电火花）、波塞冬（海浪 / 怒涛 / 涌泉）、阿瑞斯（流血 / 吸血 / 狂暴叠层）、赫尔墨斯（移速 / 翻滚 / 攻速 / 冲刺强化）、赫菲斯托斯（锐锋 / 迅击 / 分裂，改的是武器本身）。
- **统一修正管线**：`BoonManager` 暴露 `modify_attack_damage / modify_move_speed / modify_roll_iframe / modify_roll_speed / modify_attack_duration / modify_weapon`，每张卡提供同名 hook。玩家读数值时统一过管线，卡只负责声明自己能改什么。
  - 好处：新增一张卡 = 新增一个工厂分支 + 一段行为，**不侵入玩家/敌人主逻辑**；也不需要在 `player.gd` 里堆 `if zeus_chain...` 的散装判断。
- **订阅生命周期严格对称**：卡在 `on_granted()` 时才连 `EventBus` 信号，`on_removed()` 断开——避免「没持有这张卡却已生效」的幽灵状态，也保证替换卡片后旧效果真的下线。

### 3. 房间与路线（`room.gd` / `room_director.gd` / `room_spec.gd`）

- **程序化建房**：墙体、门、出口触发区、门上徽章全部运行时生成，而非手摆场景，因此能任意生成不同房间。
- **四面拓扑**：玩家进来的那扇门作为入口（常闭），其余 3 扇是出口；踏入某扇出口 → 下一关入口自动设为**对侧**，一路无缝衔接。
- **路线是数据**：每扇门挂一个 `RoomSpec`（`RefCounted`），类型 `COMBAT / ELITE / MERCHANT / BOSS`，各自决定敌人数与奖励偏斜。`Room` 只负责读规格盖房子，难度公式集中在 `RoomDirector`，不散落。
- **难度曲线**：敌人数按房号由 `RoomDirector.wave_count_for` 统一计算，精英按「每 N 房」出现。

### 4. 局外成长（`meta_state.gd` / `save_room.gd` / `statue.gd` / `weapon_rack.gd`）

- **英灵碎片**：击杀与推关获得，死亡结算时持久化到 `user://meta.save`。
- **永久加成**：碎片解锁血量上限（+25）、开局金币（+15）等。
- **5 座神像**：按 F 供奉，从该神卡池里三选一。
- **5 个武器架**：碎片解锁，解锁后可按 F 装备。
- 存档房既是开局 Hub 也是唯一的局外操作台。

### 5. 表现与交互（`juice.gd` / `audio_manager.gd` / `fx/floating_text.gd`）

- **Hitstop 顿帧** + **受击震屏**（按衰减曲线回落）+ **伤害飘字**。
- **音频对象池**：`AudioManager` 用固定 16 路 `AudioStreamPlayer` 轮询复用；同一事件多个变体随机播放、带音高抖动与最小间隔去抖，避免爆音和重复感。
- **输入设备自适应**：`InputDevice` 监测手柄（摇杆阈值 0.3 防漂移）与键鼠的切换，所有 UI 按键提示通过 `hint(action)` 统一取值，不散在各处写死。

## 架构

核心痛点是：Godot 的 `change_scene_to_file()` 会销毁旧场景，所以「单局进度」绝对不能挂在玩家节点上。分层就是围绕这一点展开的。

```
┌──────────────────── Autoload 常驻单例层 ────────────────────┐
│ EventBus     事件总线（跨场景解耦）                          │
│ RunState     单局状态：血量/等级/金币/房号（跨场景保留）     │
│ MetaState    局外成长与存档：碎片、解锁                       │
│ BoonManager  祝福修正管线 + 持有集合                          │
│ AudioManager 音频对象池   Juice 顿帧/震屏   InputDevice 输入  │
│ PauseGuard   暂停所有权   InventoryUI 背包  DeathUI 死亡面板  │
└──────────────────────────────────────────────────────────────┘
                          ▲ 信号 / 读写
┌──────────────────── 场景层（change_scene 切换）─────────────┐
│ SaveRoom（Hub）  MainRoom（Room + RoomDirector + RoomSpec）  │
│ BossRoom（Boss + BossExit）                                  │
└──────────────────────────────────────────────────────────────┘
                          ▲ 子节点 / 运行时生成
┌──────────────────── 实体层（世界内对象）────────────────────┐
│ Player  Enemy（四态状态机）  Boss（三阶段）                   │
│ 投射物（敌/我/弹幕/AOE）  Statue / WeaponRack / Merchant      │
│ DropItem / PickupItem / BossExit                              │
└──────────────────────────────────────────────────────────────┘
                          ▲ 实例化 / 读取
┌──────────────────── 数据层（非场景）────────────────────────┐
│ Boon（Resource，数据+行为合一）  RoomSpec（RefCounted）       │
│ Items（静态消耗品注册表）  WEAPONS / CARD_IDS 等数据表        │
└──────────────────────────────────────────────────────────────┘
```

### 几个刻意的设计取舍

1. **什么时候用事件总线，什么时候直接调用？**
   可能「有多个监听者、也可能没有监听者」的事件走 `EventBus`（命中、击杀、清房、开商店）；需要保证**有且只有一次**结算的交互直接调用（例如玩家调 `enemy.take_damage()`）。全走总线会让结算次数变成不可控变量。
2. **祝福用「数据 + 行为合一」的 `Resource`，而不是配置表 + 中心化 switch。**
   每张卡自带数值与钩子，`_apply_level()` 负责等级缩放，改数值不用动其他地方。
3. **房间规格用 `RefCounted` 而不是 `Node`。**
   路线是纯数据，没有生命周期需求，不该占场景树。

## 工程难点

从「能跑」到「不炸」中间踩过的坑，挑几个有代表性的：

**1. 切场景把单局进度清零**
血量、等级、金币原本挂在 `Player` 上，一进下一关就全没了。改成 `RunState` 常驻单例承载，`Player` 只读写它、`HUD` 监听它的信号。**教训：先想清楚状态的存活周期，再决定它挂在哪。**

**2. 物理回调里不能安全地改场景树**
`body_entered` 发生在物理 flushing 阶段，此时 `add_child` 或调整碰撞体会报错或产生不可预测结果。所有「进触发区 → 换房间 / 清掉落 / 开出口」一律 `call_deferred()` 延后到安全帧。
附带一个坐标坑：生成掉落物要**先 `add_child` 入树再设 `global_position`**（入树后 Godot 才会自动换算回 local），否则位置对不上。

**3. 翻滚穿怪不能靠定时器恢复碰撞**
翻滚时把碰撞掩码降到只撞墙，翻滚结束再恢复——听起来对，实际会被糊回怪堆：怪群两三层厚度可以超过翻滚位移（约 134px）。改成「幽灵态」：保持掩码，每帧检测与敌人是否仍重叠，确认穿出才恢复；外加 1.5s 超时兜底，防止被 360° 包住时永久虚无。

**4. 多个伤害源同帧致死，死亡逻辑跑两遍**
玩家血量的扣减来自多个来源（接触、弹幕、AOE），同一帧可能被判定多次死亡，导致结算面板弹两次、碎片重复给。用 `_died` / `_dying` 标志位把死亡流程做成幂等——**这是安全关键流程的基本功**。

**5. 暂停期间排队的输入会「延迟引爆」**
祝福三选一 / 商店打开时游戏暂停，但之前按下的 F 还在输入队列里，恢复瞬间误触发交互。解决：在 `NOTIFICATION_PAUSED / UNPAUSED` 清空瞬时交互队列与速度；并用 `PauseGuard` 管理「谁在占用暂停」（选卡、商店、背包、死亡面板可能同时想暂停）。
**暂停不是简单设个 `get_tree().paused = true`。**

**6. 敌群互相挤成一坨**
最初做两两分离检测，敌人一多就是 O(n²)。改成**空间哈希网格**：按格桶索引，只采样 3×3 邻格，并给单帧邻居数设上限。同样是 O(n) 级。

**7. 节点释放后 `await` 协程回来报错**
死亡红闪之类的效果如果用 `await` 协程实现，节点被释放后协程恢复会报错。改用 `Timer` / 计时变量驱动，生命周期跟着节点走。

## 已知限制

诚实说明，避免误会：

- **没有自动化测试**。这个项目的验证方式一直是手动跑游戏；作者另一个 Godot 项目（`pixel-roguelite-v2`）有 18 个 headless 测试脚本，本项目还没补上，属于明确的欠账。
- **Git 历史只有 1 次提交**（仓库是整体初始化后上传的），所以提交记录不能反映真实的开发迭代过程。
- **美术与音频是第三方素材**（Kenney、OpenGameArt 等，CC0 / CC-BY，见 `assets/*/ATTRIBUTION.md`），不是自制。我负责的是玩法、系统与工程实现。
- **没有导出成品**。需要自己用 Godot 打开运行，暂无可下载的构建产物。
- **脚本平铺在根目录**，没有按 `systems/`、`entities/`、`ui/` 分目录。功能上是分层的，物理目录上还没分层。
- **数值平衡未系统调优**，祝福等级曲线与敌人成长是按手感拍的，没有做过数据化验证。
